---
npm/@listmonk-ops/mcp: minor (Removed)
---

Removed the legacy MCP tools that mutated Listmonk without the shared confirmation and audit policy gate: `listmonk_delete_subscribers_by_query` and `listmonk_blocklist_subscribers_by_query` (an arbitrary SQL expression such as `1=1` deleted or blocklisted every subscriber in one unconfirmed, unaudited call), `listmonk_update_settings` (a raw `PUT /api/settings` passthrough that reloads Listmonk), and `listmonk_send_subscriber_optin` (an unaudited duplicate of `listmonk_send_optin`). Every mutating MCP tool is now a shared operation behind the policy gate. To migrate, resolve subscriber IDs with `listmonk_get_subscribers` (`query`) and call `listmonk_delete_subscriber` or `listmonk_blocklist_subscribers` (with optional `dry_run`) with `confirm: true`; call `listmonk_send_optin` with the same `id`; and read settings with the redacted `listmonk_get_settings`, changing them in the Listmonk admin UI. The remaining read-only transport-specific tools (`listmonk_health_check`, `listmonk_get_server_config`, and `listmonk_get_campaign_running_stats`) now publish read-only tool annotations, so clients no longer treat them as destructive. A registry test requires complete annotations on every tool and policy-gate coverage for every mutating tool. The server now registers 139 tools instead of 143.
